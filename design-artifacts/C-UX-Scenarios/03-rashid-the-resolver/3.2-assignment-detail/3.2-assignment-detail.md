# Assignment Detail (Rashid's job page)

**Route:** `/field/jobs/{ticket_id}`
**Scenario:** Rashid the Resolver — Fixes his first job of the day (screen 2 of 5)
**Purpose:** Give Rashid everything he needs to do the job — where, what's broken, the citizen's note, the dispatcher's note — and the action buttons to start work.

> **Phase B (2026-10-04):** Assignment Detail is now a **centered content column (max-width 720px) below a top bar** at all viewports. The column reflows cleanly down to phone widths. The "Start work" CTA is in-flow at the bottom of the column, not sticky-bottom. The photo block + map snippet + notes stay readable down to 360px. See `_progress/00-design-log.md` for the re-skin.

---

## User Context

Rashid has arrived on-site. He pulls up the job on his phone to confirm he is at the right spot, see the photo of the broken thing, read any notes, and tap "Start work." He may be standing, wearing gloves, and squinting at the phone. Big buttons, big photo, plain text.

## Content & Actions

### Page container

- **Page name:** `field-assignment-detail-page`
- **Language:** Bangla default.
- **Layout:** Web-first. Top bar (`--header-height-desktop` at large, `--header-height-mobile` at medium / phone widths) + a **centered content column (max-width 720px)** on `--color-surface-page`. Inside the column: photo block, location block, metadata block, notes block, and the **in-flow "Start work" CTA** at the bottom.
- **At phone widths (≤ 480px):** the column shrinks to 360px; touch targets stay ≥ 56px; the photo block shrinks in height (160px instead of 240px); map snippet stays 200px tall and full-column-width.
- **Background:** standard light theme here. `.theme-outdoor` is reserved for the Status: In Progress page (where Rashid is hands-busy and staring at the screen).

### Top bar

- **`field-assignment-topbar`** — same surface and height tokens as the rest of the app's top bars.
- **Left:** back arrow `<`. Routes to `/field` (home).
- **Center:** "কাজ #{ticket_id}" / "Job #{ticket_id}".
- **Right:** kebab menu (⋯). Options: Call dispatcher, Copy address.

### Photo block (inside content column)

- **`field-assignment-photo-block`** — full-column-width image, 240px tall on tablet/desktop, 160px tall on phone widths.
- The "before" photo from the citizen.
- Pinch-to-zoom supported.

### Location block (inside content column)

- **`field-assignment-location-block`** — compact card.
- Address text (large, primary).
- Static map snippet (Leaflet, full-column-width at all viewports, 200px tall).
- "ক্রু থেকে দূরত্ব: ৩০ মিটার / 30 m away" (computed from last check-in).
- Tap → opens full-screen map view.

### Metadata block (inside content column)

- **`field-assignment-meta`** — labeled rows:
  - **Category** — e.g., "রাস্তার আলো / Streetlight"
  - **Submitted** — "আজ ৭:৩২ PM · ২ ঘণ্টা আগে / Today 7:32 PM · 2 hours ago"
  - **Department** — "বৈদ্যুতিক বিভাগ / Electrical Department"
  - **Reporter count** — "৪ জন / 4 reporters"

### Notes block (inside content column)

- **`field-assignment-citizen-note`** — quoted block, if Rahim added one.
- **`field-assignment-dispatcher-note`** — quoted block, if Habib added an instruction note at assignment time. This is the *critical* block — Rashid checks it first.

### Primary action (in-flow, bottom of content column)

- **`field-assignment-button-start-work`** — primary CTA, in-flow at the bottom of the column, full-column-width, `--touch-cta` (64px) tall. **Not** sticky-bottom.
  - **Label (BN):** "কাজ শুরু করুন"
  - **Label (EN):** "Start work"
  - Tap → POSTs `{ticket_id, status: "in_progress"}` to `/api/v1/field/jobs/{id}/start`. Routes to Status: In Progress page (see spec).

### Secondary actions (in-flow, below CTA at all viewports)

- **`field-assignment-button-cant-find`** — text link below primary.
  - **Label (BN):** "জায়গা খুঁজে পাচ্ছি না / Can't find the spot"
  - Tap → opens a sub-flow (calls dispatcher, takes a photo of surroundings).
- **`field-assignment-button-need-help`** — text link.
  - **Label (BN):** "সাহায্য প্রয়োজন / Need help"
  - Tap → opens dispatcher chat (or call).

## Behavior

### Start work flow

1. Tap Start work → button shows spinner; disabled.
2. App POSTs `{status: "in_progress"}` to the backend.
3. **On 200 OK:** ticket status updates; app routes to `/field/jobs/{id}/progress` (Status In Progress spec).
4. **On 5xx / network failure:** toast + retry; status remains "routed."

### Distance computation

- "30 m away" uses last-known location from a previous "Start work" tap on a nearby job, or Rashid's manual check-in. If unknown, shows "দূরত্ব গণনা করা যাচ্ছে না / Distance unavailable."

### Map snippet interactivity

- Tap map → opens full-screen map view with a route suggestion overlay.

### Dispatcher note visibility

- The dispatcher's note is shown **above** the citizen's note, because it is operationally more important.

### Offline behavior

- If offline, "Start work" is queued and processed on reconnect. App routes to the In Progress page optimistically.

## States

### Default (status = routed)

Photo + address + dispatcher note + Start work CTA.

### Loading

Skeleton photo + map + metadata.

### Started (status = in-progress)

Header badge shows "চলমান / In progress." Start work button is replaced by "কাজ চালিয়ে যান / Continue work" linking to the In Progress page.

### Dispatcher note absent

Citizen note (if any) is the only note shown.

### Offline

Slim banner; Start work still functional (queues locally).

### Cannot find spot

Sub-flow open; main page dims.

## Success

Rashid arrives at the pole, pulls up the job, sees the photo, sees the dispatcher's note ("check the fuse box on pole #14"), taps Start work, gets in. Total time: under 20 seconds.

**Emotional outcome:** Rashid feels **briefed and ready**. The job page gave him what he needed without him asking.

## Open Questions

- **Dispatcher chat** — built-in chat thread vs. tap-to-call. **Default for v1: tap-to-call** (simpler; lower infra). In-app chat is a v1.1 enhancement.
- **Live location broadcast** — should Rashid's phone broadcast location while on a job? **Default for v1: no.** Privacy + battery concerns.
