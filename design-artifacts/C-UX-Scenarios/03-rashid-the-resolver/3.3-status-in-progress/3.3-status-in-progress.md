# Status: In Progress (live work view)

**Route:** `/field/jobs/{ticket_id}/progress`
**Scenario:** Rashid the Resolver — Fixes his first job of the day (screen 3 of 5)
**Purpose:** Give Rashid a live, hands-busy view of the job he's working on — minimal taps, clear status, and a big "Done" button when finished.

> **Phase B (2026-10-04):** Status: In Progress is a **full-bleed page** at every viewport — this is Rashid's hands-busy screen and it owns the entire viewport (no top bar, no centered column, no chrome). The `.theme-outdoor` high-contrast treatment applies at every viewport (UX Review revision #4). At phone widths the same full-bleed layout fits the device naturally; at tablet/desktop the same content scales up — the page is meant to be glanceable from arm's length. See `_progress/00-design-log.md` for the re-skin.

---

## User Context

Rashid is mid-job. His hands are often full — tools, gloves, climbing a ladder. He needs to see what job he's on, log progress, and tap "Mark fixed" when done. He should not need to navigate — this page is the **only thing on his screen while he works**.

---

## Content & Actions

### Page container

- **Page name:** `field-job-progress-page`
- **Language:** Bangla default.
- **Layout:** Web-first **full-bleed**. The page owns the entire viewport at every breakpoint — there is no top bar, no centered column, no app chrome on this page. Layout is single column, large type, big buttons.
- **At all viewports:** the page uses the `.theme-outdoor` CSS class. The token overrides turn `--color-surface-page`, `--color-surface-card`, `--color-ink`, `--color-border`, and `--color-primary` into the high-contrast outdoor palette (near-white surfaces, pure-black ink, near-black primary).
- **Background:** **Outdoor high-contrast theme** — near-white background with pure-black text. No greys. Designed for direct-sunlight readability on LCD and OLED (counterintuitively, dark mode increases glare on LCD in bright ambient light). Auto-switches if the device's ambient-light sensor reports high lux (> 10,000); otherwise stays in this theme by default while a job is in progress.

### Header (in-flow, top of full-bleed page)

- **`field-job-progress-header`** — height 64px, sticky to top of viewport (full-bleed). Uses the outdoor token palette (black ink on near-white surface).
- **Left:** minimize button (↓). Routes back to `/field` (does **not** stop the job — "In progress" persists on the server).
- **Center:** "চলমান কাজ / Job in progress."
- **Right:** timer — "০০:১৪:২২" — elapsed time since Start work tap.

### Hero block

- **`field-job-progress-hero`** — large card.
- Photo of the broken thing (thumbnail, 120×120, top-left).
- Category + address (large type).
- "শুরু হয়েছে {time} আগে / Started {time} ago."

### Step log

- **`field-job-progress-step-log`** — vertical list of small step entries.
- **Entries:**
  - "কাজ শুরু হয়েছে / Work started" — {time}
  - "প্রতিবেদনে যোগ করুন / Add a progress note" — input
- Each entry is a quick-tap button or composer.

### Progress note composer

- **`field-job-progress-note-input`** — collapsible textarea, 200 chars.
- **Label (BN):** "অগ্রগতির নোট যোগ করুন (ঐচ্ছিক)"
- **Label (EN):** "Add a progress note (optional)"
- Submitting appends to the step log and pushes to the dispatcher's monitor view.

### Secondary actions

- **`field-job-progress-button-pause`** — secondary button.
  - **Label (BN):** "বিরতি দিন"
  - **Label (EN):** "Pause"
  - Tap → marks the job as paused on the server; status pill changes to "বিরতি / Paused" (yellow).
- **`field-job-progress-button-escalate`** — text link.
  - **Label (BN):** "সমস্যা — প্রেরণ করুন"
  - **Label (EN):** "Issue — escalate"
  - Tap → opens escalate sub-flow (write a reason; routes back to dispatcher with the ticket).

### Primary action (in-flow, bottom of full-bleed page)

- **`field-job-progress-button-mark-done`** — primary CTA, in-flow at the bottom of the page (not sticky), full-width inside the content area, 64px tall, **high contrast (green-tinted)**. The bottom-of-page placement is intentional on this hands-busy screen: Rashid's thumb reaches there naturally on a phone, and on tablet/desktop the same content reads at arm's length.
  - **Label (BN):** "সমাধান হয়েছে — ছবি তুলুন"
  - **Label (EN):** "Fixed — take photo"
  - Tap → routes to `/field/jobs/{ticket_id}/resolve` (Resolve: Before/After Capture spec).

## Behavior

### Auto-save

- Every progress note submitted is auto-saved to the server. If offline, queued for sync.

### Timer persistence

- Elapsed timer continues across page navigations (it's tied to the server-side "started_at" timestamp, not local).

### Pause behavior

- Pausing does not stop the timer; it just changes the pill color and flags the job for dispatcher attention. The dispatcher can choose to reassign or unpause.

### Escalate behavior

- Opens a small composer modal. Reason is sent to the dispatcher, ticket reverts to "routed" with a flag.

### Lock-screen behavior (PWA)

- The page registers a service-worker wakeup so a paused job can ping Rashid after a long idle (e.g., he went for lunch).

---

## States

### Default (in progress)

Hero + step log + Mark done CTA.

### Note added

New entry visible at the top of the step log.

### Paused

Pill changes to yellow; Mark done still enabled (work can continue).

### Escalated

Modal closes; ticket reverts to routed; app routes to `/field` with a small toast: "প্রেরণ সম্পন্ন — পরবর্তী কাজ দেখুন / Escalated — see next jobs."

### Offline

Slim banner; notes are queued; Mark done routes to resolve page optimistically.

### Long-running (>2 hours)

A subtle nudge appears at the top: "এই কাজ দীর্ঘ সময় ধরে চলছে — সাহায্য দরকার? / This job has been running a while — need help?" with a tap-to-escalate.

---

## Success

Rashid works the job, adds one quick note ("found the fuse blown"), taps Mark fixed when done. The page captures his entire work session in 2 taps and 1 note.

**Emotional outcome:** Rashid feels the platform **stays out of his way** while he works. The only thing he had to learn was "tap Mark fixed when you're done."

---

## Open Questions

- **Auto-detect "long-running" threshold** — 2 hours is a guess. **Default for v1: 2 hours**, configurable per-category in admin settings.
- **Voice notes** — Rashid may want to dictate notes while his hands are full. **Default for v1: no.** Voice-to-text is a v1.1 enhancement.
