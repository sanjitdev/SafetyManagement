# Daily Queue Dashboard (Habib's morning view)

**Route:** `/dispatch`
**Scenario:** Habib the Handler — Runs his ward's morning queue (screen 2 of 7)
**Purpose:** Give Habib a calm, sorted view of every ticket in his jurisdiction, ranked by what needs him next.

---

## User Context

Habib lands on the page right after login. He has 30 minutes before his first meeting. He scans the queue, picks three tickets to action now, and lets the rest wait. This page is **his cockpit** — the place where city-corp work meets CityFix tickets.

---

## Content & Actions

### Page container

- **Page name:** `dispatch-dashboard-page`
- **Language:** Bangla default.
- **Layout:** Three-region desktop layout (top: filter rail, left: ticket list, right: detail preview pane). Collapses to single-column list + tap-to-open detail on tablet and below.
- **Width:** full-viewport on desktop; capped at 1280px on large screens.

### Top bar

- **`dispatch-dashboard-topbar`** — height 64px, sticky.
- **Left:** CityFix logo + city selector ("ঢাকা উত্তর সিটি কর্পোরেশন / Dhaka North City Corporation") — non-editable here, set at login.
- **Center:** scope indicator — "ওয়ার্ড ১৪ · মিরপুর" / "Ward 14 · Mirpur" — Habib's assigned ward. Tap → opens scope switcher (multi-ward dispatchers can swap; see Behavior).
- **Right:** user menu (avatar, name, sign out).

### Filter rail (above the list)

- **`dispatch-dashboard-filter-row`** — horizontal pill row.
- **Pills:**
  - "সব / All" (default)
  - "নতুন / New"
  - "বরাদ্দ হয়নি / Unassigned"
  - "চলমান / In progress"
  - "আজকের সমাধান / Resolved today"
- Each pill shows a count badge to the right of the label.
- Tap a pill → re-filters the list.

### Ticket list (left region, ~480px wide on desktop)

- **`dispatch-dashboard-ticket-list`** — vertical scroll.
- **`dispatch-dashboard-ticket-row-{ticket_id}`** — each row shows:
  - Thumbnail (56×56, left-aligned)
  - Category icon + label
  - Ward + age label ("২৩ মিনিট আগে / 23 min ago")
  - Status pill
  - Reporter count if dedup has rolled up multiple citizens ("৪ জন রিপোর্টার / 4 reporters")
  - Priority indicator if SLA is at risk (red dot, top-right of row)
- Default sort: priority-first (SLA risk → age → unassigned). User can switch to "oldest first."
- Pull-to-refresh at the top.
- Pagination: 50 per page; infinite scroll.

### Detail preview pane (right region, fills remaining width)

- **`dispatch-dashboard-detail-pane`** — shown when a row is selected.
- Initially empty: shows a calm empty state with copy "একটি রিপোর্ট নির্বাচন করুন / Select a ticket to preview."
- When a row is selected: shows a compact preview of the ticket (photo + metadata + status trail + actions). Tapping the preview opens the full ticket detail at `/dispatch/tickets/{id}` (see spec).

### Bulk action bar (sticky at bottom when 1+ rows selected)

- **`dispatch-dashboard-bulk-bar`** — appears when 1+ tickets are selected (checkbox on the left of each row).
- **Label:** "৩টি নির্বাচিত / 3 selected"
- **Actions:**
  - `dispatch-dashboard-bulk-assign` — "ক্রুতে বরাদ্দ করুন / Assign to crew"
  - `dispatch-dashboard-bulk-reroute` — "বিভাগ পুনঃনির্দেশ / Re-route department"
  - `dispatch-dashboard-bulk-export` — "CSV রপ্তানি / Export CSV"
- Tap an action → opens the corresponding bulk flow (modal).

### Quick stats strip (between filter rail and list)

- **`dispatch-dashboard-stats-strip`** — four small stat cards in a row.
- **Cards:**
  - "আজকের নতুন / New today" (count)
  - "এই মুহূর্তে বরাদ্দহীন / Unassigned right now" (count)
  - "চলমান / In progress" (count)
  - "গড় সমাধানের সময় / Avg time to resolve" (e.g., "৩.২ দিন / 3.2 days")
- Each card is tappable; tapping filters the list by that metric.

## Behavior

### Real-time updates

- List subscribes via polling every 10s (Habib's pace is faster than Rahim's — he needs fresher state).
- New items animate in at the top with a soft pulse.
- SLA-risk items flash once when they cross the threshold.

### Scope switching

- If Habib is assigned to multiple wards: tapping the scope indicator opens a small dropdown listing his wards; selecting one re-filters the entire dashboard.
- Single-ward dispatchers see the scope indicator as static text.

### Row interaction

- Click row → row highlights; detail pane updates with the preview.
- Double-click row → opens the full ticket detail at `/dispatch/tickets/{id}`.
- Right-click row (desktop) → context menu with: Open, Assign, Re-route, Mark duplicate, Copy ID.

### Filtering persistence

- Selected filter pill is persisted in local storage and restored on next login.

### Keyboard shortcuts (desktop)

- `J` / `K` — next / previous row.
- `A` — assign selected row to crew.
- `R` — re-route selected row.
- `Enter` — open full ticket detail.
- `/` — focus filter rail.
- `?` — show shortcut sheet.

---

## States

### Default

Stats strip + "All" pill selected + ticket list sorted by priority. Detail pane shows empty state.

### Filtered

List narrows to match the pill; stats strip stays unchanged (shows global numbers).

### Selection

One or more rows checked; bulk action bar appears at the bottom.

### Loading

Skeleton rows in the list; stats strip shows placeholders.

### Empty (no tickets in scope)

Centered empty state: "এই মুহূর্তে কোনো রিপোর্ট নেই" / "No reports right now." With a small celebratory sub-line "দারুণ — শহর এখন শান্ত" / "Nice — the city is quiet right now."

### Network failure

Slim banner at the top: "আপডেট পেতে সমস্যা হচ্ছে" / "Updates paused." Polling retries automatically.

## Success

Habib opens the dashboard, sees 17 tickets in his queue, identifies the 3 most urgent in under 30 seconds, opens the first one to start routing. He is in flow within 60 seconds of login.

**Emotional outcome:** Habib feels the city is **legible** from this page. Every ticket has a place. He is not hunting for information — the platform surfaces what needs him.

---

## Open Questions

- **Detail pane vs. full route** — keep the preview pane, or always navigate to `/dispatch/tickets/{id}`? **Default for v1:** preview pane for scan, full route for action. Power-users can disable the pane in settings.
- **Priority algorithm** — the "priority-first" sort is weighted by SLA risk. The exact weights are a v1.1 tuning task based on Dhaka's actual SLA windows per category.
