# Login (Web / Desktop)

**Route:** `/login`
**Scenario:** Habib the Handler — Runs his ward's morning queue (screen 1 of 7)
**Purpose:** Give Habib a fast, no-nonsense login that gets him into the dispatch console without ceremony.

---

## User Context

Habib opens his work laptop, pulls up cityfix.gov.bd/dispatch, and wants to be inside the queue in under 15 seconds. He is a government employee with city-corp SSO already enabled on this machine, but he has been told to use the CityFix login for the first month while SSO is rolled out. He logs in dozens of times a day as he switches between CityFix and other work tools — this page should never get in his way.

---

### Page container

- **Page name:** `dispatch-login-page`
- **Language:** Bangla default.
- **Layout:** Centered card on a calm neutral background. Two-column on desktop (left: brand panel, right: form), single-column on tablet and below.
- **Width:** form column capped at 420px on desktop; full-width on mobile.

- **`dispatch-login-brand-panel`** — visible on viewports ≥ 1024px.

## Behavior

### Submit flow

1. Tap Submit → button shows spinner; inputs disabled.
2. App POSTs `{identifier, password, remember_device}` to `/api/v1/auth/login`.
3. **On 200 OK:** JWT is stored; app routes to `/dispatch` (Habib's daily queue dashboard — see spec).
4. **On 401 invalid credentials:** inline error above submit: "ভুল তথ্য — আবার চেষ্টা করুন" / "Wrong credentials — try again."
5. **On 423 locked:** inline error with lockout duration: "অতিরিক্ত চেষ্টা — ১৫ মিনিটের মধ্যে আবার চেষ্টা করুন" / "Too many attempts — try again in 15 minutes."
6. **On 5xx or network failure:** toast at bottom: "সংযোগ ব্যর্থ — আবার চেষ্টা করুন" + retry button.

### Remember device

- When checked, JWT lifetime extends to 30 days. Refreshes silently in the background while the device is in use.
- When unchecked, JWT lifetime is 8 hours (workday).

### Keyboard behavior

- `Enter` on either field submits the form.
- `Tab` order: identifier → password → remember → submit → forgot → contact IT.

### Auto-fill

- Form supports browser auto-fill for institutional credentials (Habib's city-corp credentials may be pre-populated by his password manager).

### Session check

- On page load: if a valid JWT exists in storage, skip this page and route to `/dispatch` directly.

---

## States

### Default

Empty form, Submit enabled, no errors.

### Filling

User types — Submit enables when both fields have content.

### Submitting

Spinner on Submit; inputs disabled.

### Invalid credentials

Inline error above submit; password field cleared; identifier preserved.

### Locked

Inline error with countdown; both inputs disabled; lockout lifts automatically.

### Network failure

Toast at bottom; Submit re-enabled.

### Already signed in

Page redirects to `/dispatch` before render.

---

## Success

Habib types his staff ID and password, taps Enter, lands inside his queue dashboard. Total time inside the login page is 6–10 seconds.

**Emotional outcome:** Habib's first impression is that the platform respects his time. There is no marketing fluff, no registration gate (he is internal staff), and no surprise — just a clean login that works.

## Open Questions

- **SSO hand-off** — when city-corp SSO is fully rolled out, this page collapses to an SSO-only flow. **Default for v1:** keep this form active; SSO is a v1.1 enhancement.
- **Mobile identifier format** — staff ID vs. mobile number vs. email. **Default for v1:** accept any of the three; the backend resolves to a single account.
