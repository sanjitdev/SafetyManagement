# Monitor Updates (live ticket feed)

**Route:** `/dispatch/tickets/{ticket_id}` (tabbed view) or `/dispatch/monitor`
**Scenario:** Habib the Handler — Runs his ward's morning queue (screen 5 of 7)
**Purpose:** Give Habib a focused view of what's happening on his assigned tickets, in real time, without leaving the dispatcher surface.

---

## User Context

Habib has assigned 7 tickets this morning. He wants to glance at one of them to see if Rashid has marked it "in progress" yet, or if the citizen has responded with more context. He does not want to navigate through a full ticket-detail page each time — he wants a thin panel that updates live.

---

## Content & Actions

### Page container

- **Page name:** `dispatch-monitor-page`
- **Language:** Bangla default.
- **Layout:** Single-column list. Each entry expands inline to show the latest updates. On desktop, the right side hosts a summary chart strip (see below).
- **Width:** capped at 960px; full-width on mobile.

### Header

- **`dispatch-monitor-header`** — height 56px.
- **Left:** back arrow `<`. Routes to `/dispatch`.
- **Center:** "লাইভ আপডেট / Live updates."
- **Right:** filter chips. "সব / All" (default), "আমার ওয়ার্ড / My ward", "আমার ক্রু / My crews."

### Live activity list

- **`dispatch-monitor-list`** — vertical scroll of "watched tickets."
- **`dispatch-monitor-row-{ticket_id}`** — each row:
  - Photo thumbnail (40×40)
  - Category + ward
  - Status pill (color-coded)
  - Most-recent activity snippet: "রশিদ ৫ মিনিট আগে 'চলমান' চিহ্নিত করেছেন / Rashid marked 'In progress' 5 min ago"
  - Unread dot if there is an unread update
- Each row is expandable: clicking it reveals a small panel with the last 3 status-trail steps and any new photos uploaded since last read.

### Empty state

- If Habib has no assigned tickets: "এই মুহূর্তে কোনো টিকিট আপনার কাছে নেই / No tickets on your queue right now." With a link back to the dashboard.

### Desktop summary chart strip (right column)

- **`dispatch-monitor-chart-strip`** — visible on desktop, ~280px wide.
- Three small charts stacked vertically:
  - "আজকের প্রবাহ / Today's flow" — a horizontal stacked bar showing Submitted → Routed → In progress → Resolved.
  - "গড় প্রতিক্রিয়া সময় / Avg response time" — last 7 days, sparkline.
  - "ক্রু লোড / Crew load" — small bar chart per crew.

---

## Behavior

### Real-time updates (primary feature)

- Page subscribes via WebSocket (preferred) or polling every 5s (fallback).
- New updates animate in at the top of their row with a soft pulse.
- An aggregate counter at the top shows "৩টি নতুন আপডেট / 3 new updates" since the page was opened; tapping it scrolls to the latest.

### Expansion

- Click row → row expands inline to show recent trail steps.
- Click again → collapses.
- Tapping the expanded panel opens the full ticket detail in a new route.

### Mark as read

- Expanding a row marks all updates on that ticket as read. The unread dot clears.

### Acknowledge button (per row)

- **`dispatch-monitor-row-acknowledge`** — small "✓" button at the right of each row.
- Tap → quietly acknowledges the update without opening the row (for when Habib just wants to clear the notification visually).

### Chart interactivity

- Charts are static for v1 (read-only). Tapping a chart bar filters the list to that category (e.g., "In progress" → list narrows).

---

## States

### Default

List of watched tickets sorted by most-recently-updated; chart strip visible on desktop.

### New updates

Aggregate counter visible; affected rows pulse on first render.

### Filtered

List narrows by ward / crew filter.

### Empty

Centered explanation + dashboard link.

### Network failure

Slim banner at top: "লাইভ আপডেট বন্ধ / Live updates paused." Polling retries.

---

## Success

Habib glances at the monitor between meetings, sees Rashid marked 4 of his 7 tickets "In progress," acknowledges 2, opens 1 to read a citizen follow-up note. Total time: under 2 minutes.

**Emotional outcome:** Habib feels **connected** to the field without leaving his desk. The distance between desk and ground is smaller than it has ever been.

---

## Open Questions

- **WebSocket vs. polling** — WebSocket is preferred for true real-time. **Default for v1:** polling at 5s (simpler infrastructure); WebSocket is a v1.1 enhancement.
- **Acknowledgment persistence** — when Habib acknowledges an update, does it notify the citizen that the dispatcher saw it? **Default for v1: yes**, a soft "হাবিব আপনার আপডেট দেখেছেন / Habib has seen your update" line on the citizen's app.
