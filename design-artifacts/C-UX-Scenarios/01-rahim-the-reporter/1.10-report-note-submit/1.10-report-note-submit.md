# Report Flow — Note (optional)

**Route:** `/report/note`
**Scenario:** Rahim the Reporter — Reports a broken streetlight (screen 10 of 14)
**Purpose:** Capture an optional free-text note from Rahim, then submit the report.

> **Phase B (2026-10-04):** Note & Submit keeps its centered-card layout but widens to a **two-column** pattern at large viewport: summary card on the left (1fr), note input + submit on the right (1fr). At medium / phone widths the columns stack (summary on top, note + submit below). The **sticky-bottom submit button is replaced** with an in-flow primary button at the bottom of the right column / below the stacked note input. See `_progress/00-design-log.md` for the re-skin.

---

## User Context

Rahim arrives here from Category Pick with location, photo, and category locked in. He is ready to send. This screen is the final gate before his report goes live.

## Content & Actions

### Page container

- **Page name:** `report-note-page`
- **Language:** Bangla default.
- **Layout (web-first, large viewport ≥ 1025px):** centered content area, max-width 960px. Inside: header (back arrow + step label), progress bar, then a **two-column grid (1fr / 1fr)** — **summary card on the left**, **note input + submit on the right**. The submit button is in-flow at the bottom of the right column.
- **Layout (medium / phone widths ≤ 1024px):** single column, max-width 640px. The summary card sits above the note input. Submit button is in-flow at the bottom.
- **At all viewports:** there is **no sticky-bottom submit**. The submit button is in-flow and reads at the same place the eye finishes scanning.

### Header

- **`report-note-header`** — height 56px.
- **Left:** back arrow `<`. Routes to `/report/category`.
- **Center:** "ধাপ ৪ / ৪: যাচাই ও পাঠান" / "Step 4 of 4: Review & submit".

### Progress indicator

4 of 4 segments filled.

### Summary card (left column at large / top at medium)

- **`report-note-summary-card`** — rounded card, white background, subtle border. Shows a compact recap:
  - **Photo thumbnail** (small)
  - **Category** label (e.g., "রাস্তার আলো / Streetlight")
  - **Ward** label (e.g., "ওয়ার্ড ১৪, মিরপুর")
  - **Detected at** timestamp (e.g., "আজ ৭:৩২ PM" / "Today 7:32 PM")
- Tap any section to edit (back-arrow style — goes to the corresponding step).

### Note input (right column at large / below summary at medium)

- **`report-note-input`** — labeled textarea, 200-character limit (Bangla and English characters both count).
- **Label:** "নোট যোগ করুন (ঐচ্ছিক)" / "Add a note (optional)".
- **Placeholder:** "কিছু বলতে চাইলে লিখুন…" / "Anything to add?"
- **Character counter** below the input: "০ / ২০০" / "0 / 200", updates live. Turns red at the limit.
- Empty is acceptable — Submit is enabled even when the note is empty.

### Primary action (in-flow, right column / below note at medium)

- **`report-note-button-submit`** — in-flow primary CTA, full-width inside the right column / below the stacked note input, `--touch-large` (56px) tall. **Not** sticky-bottom.
  - **Label (BN):** "রিপোর্ট পাঠান"
  - **Label (EN):** "Submit report"
  - Tap → POSTs the full report payload to `/api/v1/reports`.

## Behavior

### Submit flow

1. Tap Submit → button shows spinner; all inputs disabled.
2. App assembles the full report payload:
   ```json
   {
     "category": "streetlight",
     "lat": 23.806,
     "long": 90.368,
     "ward_id": "...",
     "photo": "<base64 or upload ref>",
     "note": "..."
   }
   ```
3. App POSTs to `/api/v1/reports`.
4. **On 201 Created:** ticket_id is returned; app routes to `/report/submitted?ticket_id={id}`.
5. **On 4xx validation error:** inline error at top of page with specific field errors.
6. **On 5xx or network failure:** toast "সংযোগ ব্যর্থ — আবার চেষ্টা করুন" + retry button.

### Offline submit

- If the app is offline at submit time, the report is **queued locally** and submitted on reconnect.
- The Submit button still succeeds immediately — Rahim sees the confirmation page.
- A small banner on the submitted screen notes "অফলাইনে জমা হয়েছে — সংযোগ ফিরে আসলে আপলোড হবে" / "Saved offline — will upload when reconnected" if the queue is still pending.

### Back navigation

- Back arrow → `/report/category` (location, photo, category all preserved).

## States

### Default

Summary card visible; empty note input; Submit enabled.

### With note

Same as default, plus the typed note in the input.

### Character limit reached

Counter turns red; further input blocked; Submit still enabled.

### Submitting

Spinner on Submit button; all inputs disabled.

### Validation error (server)

Inline error banner at top of page with the first field error. Inputs remain editable.

### Network failure

Toast at bottom; Submit re-enabled; user can retry.

## Success

Rahim lands here, glances at the summary card, optionally types a one-line note (or skips), taps Submit. He is routed to the Submission Confirmation screen.

**Emotional outcome:** Rahim feels the platform is **about to act on his behalf**. He has provided everything the city needs to know; the platform handles the routing. He is at the threshold of "being heard."

## Open Questions

- **Edit capability from summary card** — each summary field is tappable to edit. **Default: yes.** But for "Photo," tapping should reopen Photo Capture (replace, not add a second).
- **Character limit** — 200 chars. **Default for v1.** Higher limits (500+) considered for v2 if usage data shows truncation.
