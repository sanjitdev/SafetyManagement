# Verification (OTP)

**Route:** `/verify-otp`
**Scenario:** Rahim the Reporter — Reports a broken streetlight (screen 4 of 14)
**Purpose:** Get Rahim's 6-digit code entered and verified with minimum friction, ideally via SMS auto-read.

> **Phase B (2026-10-04):** OTP keeps its centered single-column layout (`max-width: 480px`). The **sticky-bottom CTA** is replaced with an in-flow button at the bottom of the card. The 6-digit input row is centered. See `_progress/00-design-log.md` for the re-skin.

---

## User Context

Rahim arrives here immediately after submitting the Registration form. The app has just sent an SMS containing a 6-digit verification code to his phone. His arrival state is **wary momentum**: he's past the first gate, his thumb is on the keyboard, and any delay here loses him.

He's on mobile data, possibly in patchy signal (evening commute). SMS delivery on Bangladesh networks is typically 1–5 seconds; on the worst days, longer. He expects to type a code, tap once, and be in.

- **Page name:** `verification-page`
- **Language:** Bangla default, persists from Registration.
- **Layout:** Web-first. Single column, scrollable, centered. The card is constrained to `max-width: 480px` at all viewports, sitting on a calm neutral background. Header with back arrow lives inside the column; the **Verify** button is in-flow, not sticky-bottom.

### Header

- **Left:** back arrow `<`. Tap → opens confirm dialog (see Behavior).
- **Center:** CityFix wordmark.

### Title block

  - **English:** "Verify your phone"
- **`verification-subtitle`** — body text, with masked phone number.
  - **Bangla:** "+880 1712-\*\*\*-789-এ একটি কোড পাঠানো হয়েছে।"
  - **English:** "We sent a code to +880 1712-\*\*\*-789."

  - **English:** "Wrong number? Change it"

### Code input

- **`verification-input-code`** — six single-digit boxes in a single horizontal row. Each box is ~48×56px on mobile, generous touch target.
- Auto-advances cursor to next box on each digit entered.
- Auto-submits (taps the Verify button) when the 6th digit is entered — unless auto-read is enabled and just filled the field.
- Supports paste: pasting "123456" populates all six boxes in one go.
- Backspace in an empty box returns cursor to previous box.
- Numeric keyboard only.
- Box border color: standard (TBD) by default; error border (red, TBD) when validation fails.

### Primary action

- **`verification-button-submit`** — **in-flow** (not sticky), full-width inside the 480px column, 56px tall. 24px of breathing room between the input row and the button.
  - **Label (BN):** "যাচাই করুন"
  - **Label (EN):** "Verify"
  - **State:** disabled (greyed) until all 6 digits are entered. Enabled = primary brand color, white text.
  - **Tap:** POSTs `{phone, code}` to `/api/v1/auth/verify-otp`.

### Resend code

- **`verification-link-resend`** — text link centered, below the CTA, 24px above the bottom safe area.
  - **Initial state:** "Resend in 0:60" / "0:60 সেকেন্ডে আবার পাঠান" — countdown only, not tappable.
  - **After 60s:** "Resend code" / "আবার কোড পাঠান" — tappable; tapping triggers a new SMS and restarts the timer to 60s.
  - **During resend request:** "Sending..." / "পাঠানো হচ্ছে..." — non-tappable.

## Behavior

### SMS auto-read (Android)

On Android, the app uses the **SMS Retriever API** to read the 6-digit code from incoming SMS automatically. The SMS body must be formatted with a hash that ties it to the CityFix app (per Google's spec). Integration with the SMS gateway (Twilio / SSL Wireless / BulkSMS BD / etc.) is owned by Mimir.

When auto-read succeeds: the 6 boxes fill, the cursor disappears, and Verify is auto-tapped within 400ms. Rahim sees the page for ~1.5 seconds and lands on Home.

When auto-read is unavailable (iOS Safari, denied permissions, SMS body missing the hash): the input behaves as a normal manual entry.

### Code generation and expiry

- OTP is 6 numeric digits.
- TTL: 5 minutes from issue.
- **Resend cooldown:** 60s between resends.
- **Max attempts:** 5 wrong attempts within 10 minutes → soft lockout (see Edge Cases).

### Verify flow

1. Six digits entered (or auto-filled).
2. Tap `verification-button-submit` → button shows spinner; inputs disabled.
3. App POSTs `{phone, code}` to `/api/v1/auth/verify-otp`.
4. **On 200 OK:** user is authenticated, JWT token stored in `localStorage.auth_token`. App routes to `/home`.
5. **On 401 (wrong code):** see Wrong Code state below.
6. **On 410 (expired):** see Expired Code state below.
7. **On 429 (rate-limited):** see Too Many Attempts state below.
8. **On 5xx or network failure:** toast "সংযোগ ব্যর্থ — আবার চেষ্টা করুন" — inputs re-enabled.

### Back navigation

- Tap back arrow → confirm dialog: "Leave verification? / যাচাই ছেড়ে যাবেন?" with two buttons: "Stay" / "Leave". **Leave** discards the in-progress OTP and routes back to `/welcome` (because the user hasn't logged in; on second open, Welcome is skipped). The registration form state on the previous Registration screen is preserved.

## States

### Default (waiting for code)

Six empty boxes. Cursor in box 1. Submit disabled. Resend timer counting down from 60s. Subtitle showing masked phone.

### Auto-read succeeded (Android only)

Boxes fill programmatically; submit auto-tapped within 400ms; transition to Home. **This state is shown for fewer than 2 seconds on most devices.**

### Submitting

All six inputs disabled. Submit button shows spinner and "Verifying..." / "যাচাই হচ্ছে..."

### Wrong code

Inline error below the input row, in red (TBD): "কোড মিলছে না — আবার চেষ্টা করুন" / "Code didn't match — try again." Clears on next digit entry. Boxes retain current input for 2 seconds, then clear automatically so the user can try again without manually deleting.

### Expired code

Inline error replaces the wrong-code error: "কোডের মেয়াদ শেষ — নতুন কোড পাঠান" / "Code expired — send new code." The Resend link becomes tappable immediately (timer overridden). Boxes cleared.

### Too many attempts

The whole form is replaced with a centered message: "অনেক চেষ্টা হয়েছে — কিছুক্ষণ পর আবার চেষ্টা করুন" / "Too many attempts — try again later." Below: a "Back to registration" link that returns to `/register`. **No time-display on the lockout duration in v1** to avoid leakage to attackers; just tells them to come back.

### Code not arrived

After 30 seconds with no input and no auto-read, a small helper line appears below the input: "কোড আসছে না? আবার পাঠান" / "Code didn't arrive? Resend." Shortens to one tap to recover from SMS delivery delay without making the user wait for the full 60s timer.

## Success

Rahim taps Register, gets routed to OTP. SMS lands on his phone. The 6-digit code auto-fills into the boxes (Android) and the app navigates to Home within 2 seconds. He's logged in. Total elapsed from Registration submit to Home: under 10 seconds on a healthy network.

**Emotional outcome:** Rahim's skepticism is **softened but not yet dispelled**. The OTP flow either *confirms* that CityFix is fast and respectful (good) or *creates* new friction (bad). The auto-read path is the single biggest emotional win in the entire funnel; making it work is core to trust.

## Open Questions

- **SMS provider integration** — Twilio vs. SSL Wireless vs. BulkSMS BD. Each handles SMS Retriever hash format slightly differently. **Default for v1:** whichever provider integrates fastest; defer optimization to v2.
- **iOS SMS auto-fill** — iOS Safari supports auto-fill from Messages via `<input type="text" inputmode="numeric" autocomplete="one-time-code">`. Worth implementing as a fallback even on Android fails. **Default:** include in spec; verify in browser review.
- **Lockout duration** — currently "try again later" with no timer. v2 might display an exact countdown. **Default:** opaque for v1.
- **Phone masking format** — currently "+880 1712-\*\*\*-789". Alternative: "+880 •••-•••-789" (entire mobile segment masked). **Default:** show last 3 digits so Rahim can sanity-check.
