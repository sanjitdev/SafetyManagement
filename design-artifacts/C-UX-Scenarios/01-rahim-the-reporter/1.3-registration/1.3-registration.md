# Registration

**Route:** `/register`
**Scenario:** Rahim the Reporter — Reports a broken streetlight (screen 3 of 14)
**Purpose:** Verify Rahim's identity quickly enough that his skepticism doesn't win, then route him to OTP verification.

> **Phase B (2026-10-04):** Registration keeps its centered single-column layout (`max-width: 480px` inside `--layout-mobile-max`) but the **sticky-bottom CTA** is now replaced with an in-flow button at the bottom of the form. The 56px-tall stickiness was a mobile-only pattern; on web, an in-flow button reads better inside the centered column. See `_progress/00-design-log.md` for the re-skin.

---

## User Context

Rahim arrives at registration after tapping "Register to start" on the Welcome screen. He has just installed CityFix from the app store after seeing it on Facebook. He is tired — it is evening, on his way home — and slightly annoyed that he has to register at all. He has tried official government reporting before and gave up because of the friction. He is not in a trusting mood. His hands are dirty from the commute; he is on mobile data, possibly patchy signal.

His arrival state is **skeptical and time-pressured**. He wants to either get through this gate fast or close the app.

## Content & Actions

### Page container

- **Page name:** `registration-page`
- **Language:** Bangla default (English toggle in top-right corner of the centered card).
- **Layout:** Web-first. Single column, scrollable, centered. The card is constrained to `max-width: 480px` at all viewports, sitting on a calm neutral background (`--color-surface-page`). The form and the in-flow submit button render inside this 480px column. The page is **not** full-bleed on mobile; the column is identical at 360px and 1440px viewports.

### Header

- **`registration-header`** — Back arrow (left), CityFix wordmark (center). Tap back → returns to Welcome. The header sits **inside** the 480px column at all viewports — there is no separate top bar.
- **Title:** "Create account" / Bangla: "অ্যাকাউন্ট তৈরি করুন".
- **Subtitle:** "Verify your identity to start reporting." / Bangla: "রিপোর্ট করা শুরু করতে আপনার পরিচয় যাচাই করুন।"

### Form

- **`registration-form`** — five labeled input fields, stacked vertically with 16px gap.

#### Field 1 — Phone number

- **`registration-input-phone`** — label: "Phone number" / "ফোন নম্বর". Country code prefix "🇧🇩 +880" displayed as a non-editable chip on the left. Input accepts 11-digit Bangladeshi numbers (the 0 is implicit after +880). Placeholder: "01XXX-XXXXXX". Keyboard: numeric. Maximum length: 11 digits.

#### Field 2 — NID

- **`registration-input-nid`** — label: "National ID (NID)" / "জাতীয় পরিচয়পত্র". Helper text below label: "10 or 17 digits" / "১০ বা ১৭ সংখ্যার". Placeholder: "Enter your NID". Keyboard: numeric. Maximum length: 17 digits. Pattern: 10 digits (old NID) or 17 digits (new NID).

#### Field 3 — Full name

- **`registration-input-name`** — label: "Full name" / "পুরো নাম". Helper text: "As shown on your NID" / "আপনার এনআইডি অনুযায়ী". Placeholder: "Your full name". Keyboard: text with autocapitalize=on.

#### Field 4 — Password

- **`registration-input-password`** — label: "Password" / "পাসওয়ার্ড". Helper text: "Minimum 8 characters, with at least one number" / "কমপক্ষে ৮ অক্ষর, একটি সংখ্যাসহ". Input type: password (masked). Show/hide toggle on the right. Placeholder: "••••••••".

#### Field 5 — Confirm password

- **`registration-input-confirm-password`** — label: "Confirm password" / "পাসওয়ার্ড নিশ্চিত করুন". Input type: password (masked). Show/hide toggle on the right. Placeholder: "••••••••".

### Primary action

- **`registration-button-submit`** — **in-flow** (not sticky), full-width inside the 480px column, 56px tall. Label: "Continue" / "এগিয়ে যান". Disabled state: button is disabled (greyed out, not clickable) until all 5 fields are filled AND passwords match AND password passes strength rule. When enabled: solid primary fill (`--color-primary`), white text, full-width. There is 24px (`--space-5`) of breathing room between the form and the submit button.

### Secondary actions

- **`registration-link-login`** — text link below the submit button, centered. Label: "Already have an account? Log in" / "ইতিমধ্যে অ্যাকাউন্ট আছে? লগ ইন করুন". Tap → routes to `/login`.

### Error display

- **`registration-error-{field}`** — small inline error text below each field, in red (the error color, TBD), 13px. Visible only when an error condition is true. Single error per field at a time.

## Behavior

### Validation (client-side, on field blur and on submit)

| Field | Rule | Error message (BN) |
|---|---|---|
| Phone | 11 digits, starts with 1 or 2 | "সঠিক ফোন নম্বর দিন" (Enter a valid phone number) |
| NID | 10 or 17 digits | "NID অবশ্যই ১০ বা ১৭ সংখ্যার হতে হবে" |
| Name | non-empty, ≥ 2 characters | "আপনার নাম লিখুন" |
| Password | ≥ 8 chars, contains ≥ 1 digit | "পাসওয়ার্ড কমপক্ষে ৮ অক্ষরের এবং একটি সংখ্যা থাকতে হবে" |
| Confirm password | matches password field | "পাসওয়ার্ড মিলছে না" |

### Submit flow

1. Tap `registration-button-submit` → button shows loading spinner; form inputs disabled.
2. App POSTs `{phone, nid, name, password}` to `/api/v1/auth/register`.
3. **On success (201):** app routes to `/verify-otp` with the phone number preserved in state. The OTP screen asks for the 6-digit code sent via SMS.
4. **On 409 Conflict (phone or NID already registered):** inline error appears above the form: "এই ফোন নম্বর / NID আগেই নিবন্ধিত — লগ ইন করুন।" with a tappable "Log in" link.
5. **On 4xx other:** inline error per field per the validation rules above.
6. **On 5xx or network failure:** toast at bottom: "সংযোগ ব্যর্থ — আবার চেষ্টা করুন।" (Connection failed — try again). Submit button re-enabled.

### State preservation

- If Rahim taps back or the network drops mid-submit, his form values are preserved (local state). He does not lose data on a transient failure.
- Submit button is **disabled** during in-flight request; tapping it again does nothing.

## States

### Default (empty)

All fields empty. Submit button **disabled** (greyed out). No error messages visible. Helper text visible under labels.

### Filled (valid)

All fields filled, passwords match, password passes strength. Submit button **enabled** (full color). No error messages.

### Filled (invalid)

Each invalid field shows its inline error. Submit button **disabled** while any field is invalid.

### Loading

Submit button shows spinner and label changes to "Sending..." / "পাঠানো হচ্ছে...". All form inputs disabled. No navigation possible (back arrow still works but warns: "Are you sure? Your registration isn't complete.").

### Error (registration conflict)

Inline error message at top of form: "এই ফোন নম্বর আগেই নিবন্ধিত — লগ ইন করুন" with a tappable login link. Form remains visible. Submit button returns to enabled state if fields are still valid.

### Error (server / network)

Toast at bottom: "সংযোগ ব্যর্থ — আবার চেষ্টা করুন।" Submit button re-enabled.

## Success

Rahim taps Submit, the loading state shows for ~1 second, the app routes to `/verify-otp`. The OTP screen shows his phone number with a masked middle ("+880 1712-***-789") and asks for the 6-digit code. SMS arrives within 5 seconds on Bangladesh networks.

**Emotional outcome:** Rahim's skepticism is **not yet dispelled** — he's only past the first gate. But the page must leave him feeling "this was fast, this was reasonable, this didn't waste my time." The form's quickness and the absence of marketing copy are the experience that earns him a chance to reach the OTP screen without closing the app.

## Open Questions

- **Brand color for primary CTA** — not yet decided (TBD in token extraction). Default assumption: warm orange (`#F26B2B`-ish) for civic confidence.
- **Toast vs. inline error for 5xx** — using a toast for network failures is faster to dismiss; using inline keeps errors co-located with the form. Decision: toast, because a 5xx is a transient state, not a form-validity issue.
- **Privacy notice / terms** — confirmed out of scope for v1. May need to add before public launch if required by Bangladesh government digital-service regulations.
- **NID format edge cases** — 13-digit "smart NID" exists in some pilot programs. Out of scope for v1; field validation accepts 10 or 17 only.
