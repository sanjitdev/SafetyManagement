# Report Submitted — Confirmation with Status Trail

**Route:** `/report/submitted?ticket_id={id}`
**Scenario:** Rahim the Reporter — Reports a broken streetlight (screen 11 of 14)
**Purpose:** Confirm to Rahim that his report landed somewhere and is moving, and immediately surface the status trail.

> **Phase B (2026-10-04):** This page is now the re-skinned confirmation mockup (`mockups/03-report-submitted.html`). The full-bleed mobile hero + sticky-bottom CTA is replaced with a **centered card (max-width 640px) on a neutral surface** at every viewport. The card carries a hero check + headline + ticket ID + 4-step status trail + two-button CTA pair. **Same at every viewport** — the centered card is the mobile, tablet, and desktop form. See `_progress/00-design-log.md` for the re-skin rationale.

---

## User Context

Rahim arrives here from a successful submit. He has just done something most citizens have never done: filed a city infrastructure report with status visibility. This screen is the **first concrete answer to his "am I being heard?" question**.

---

## Content & Actions

### Page container

- **Page name:** `report-submitted-page`
- **Language:** Bangla default.
- **Layout:** Web-first centered card on a calm neutral surface (`--color-surface-page`). The card is constrained to `max-width: 640px` (uses `--card-max-width` token) and centered horizontally and vertically with a generous `--space-7` top/bottom padding. The card itself is `--color-surface-card` with `--radius-lg` corners, `--shadow-md` shadow, and `--space-7` / `--space-6` internal padding.
- **At every viewport** (phone 360px → desktop 1440px), the card is identical in dimensions, padding, and content. There is no responsive reflow — only the surrounding background changes.

### Card hero

- **`report-submitted-hero`** — centered text block at the top of the card.
- **`report-submitted-check`** — a 72px circular check-mark icon, `--color-status-resolved-soft` background, `--color-status-resolved` check stroke. Centered.
- **`report-submitted-title`** — H1, centered, "আপনার রিপোর্ট গ্রহণ করা হয়েছে / Your report has been received."
- **`report-submitted-subtitle`** — body text, centered, `--color-ink-secondary`, "ধন্যবাদ। আমরা এটি সংশ্লিষ্ট বিভাগে পাঠিয়েছি। অগ্রগতি এই পেজ থেকেই দেখতে পারবেন। / Thank you. We've routed it to the responsible department — you can track progress from this page."

### Ticket ID

- **`report-submitted-ticket-id`** — centered, `--font-mono`, small caption in `--color-ink-tertiary` with the ticket ID in `--color-ink` semibold. Wrapped in a small `--color-surface-page` pill with a check-circle icon. Example: "টিকেট আইডি: #TIX-1234".

### Status trail (inside the card)

- **`report-submitted-status-trail`** — a 4-step vertical timeline rendered inside a `--color-surface-page` sunken region with `--radius-md` corners and `--space-4` padding. The trail mirrors `mockups/03-report-submitted.html` exactly:
  1. **জমা হয়েছে / Submitted** — done (filled green dot with check). Time "এইমাত্র · আপনি / Just now · You".
  2. **বৈদ্যুতিক বিভাগে রাউট হয়েছে / Routed to Electrical Department** — current (filled primary blue dot, numbered ২ / 2). Time "আনুমানিক ৪–৪৮ ঘণ্টা / Est. 4–48 hours".
  3. **মাঠ ক্রু কাজ শুরু করবে / Field crew will start work** — pending (grey dot, numbered ৩ / 3). Time "পরবর্তী / Next".
  4. **সমাধান নিশ্চিত হবে / Resolution confirmed** — pending (grey dot, numbered ৪ / 4). Time "পরবর্তী / Next".
- Vertical connector line between dots, `--color-border` (muted), turns `--color-status-resolved` as steps complete.
- Step label `--weight-semibold` body-sm; time `--text-caption` `--color-ink-tertiary`.
- **Auto-updates in real time** (via polling every 10–30s) when the server changes the ticket status. When a new step completes, the dot fills and animates with a 200ms transition.

### Offline banner (above status trail, inside the card)

- If the submit was queued offline, a slim banner above the status trail inside the card: "অফলাইনে জমা হয়েছে — সংযোগ ফিরে আসলে আপলোড হবে / Saved offline — will upload when reconnected."
- Disappears once the upload completes.

### CTAs (inside the card, two-button grid)

- **`report-submitted-button-view`** — primary, left half of the 1fr / 1fr grid. Label "রিপোর্ট দেখুন / View report". Tap → routes to `/reports/{ticket_id}`.
- **`report-submitted-button-home`** — secondary outline, right half. Label "হোমে ফিরে যান / Back to home". Tap → routes to `/home`.

### Trust line (inside the card, below CTAs)

- A small line of secondary text below the CTA pair: "আপডেট হলে আমরা আপনাকে জানাব / We'll notify you of updates" with a small shield icon. Centered, `--text-caption` `--color-ink-tertiary`.

### No top bar, no header

- The page has **no top bar / no header**. The centered card is the only content. The page is meant to be the calm, app-wide moment right after submit — chrome would dilute the focus.

## Behavior

### Status polling

- This screen subscribes to status updates for `ticket_id` from the URL parameter.
- Updates polled every 10–30s (per WO-000 platform foundation) while the screen is foregrounded.
- Each status change updates the trail inline (current step → done, next step → current).
- Stops polling when the user navigates away.

### Real-time via WebSocket (v1.1)

- If WebSocket is enabled, updates arrive in real time without polling delay.
- For v1, polling is sufficient given Bangladesh network latency.

### Offline queue upload

- If the report was queued offline, the upload happens automatically on reconnect.
- When the upload completes, the offline banner is removed and the status trail's first step timestamp is updated to the actual server time.

### Back / close behavior

- "Back to home" CTA → routes to `/home` (does not re-trigger the report flow).
- Hardware back button → same as "Back to home".

## States

### Default (online submit, status Submitted)

Hero check + headline + subtitle + ticket ID + status trail with step 1 marked complete (done) + step 2 marked current + steps 3–4 pending + two-button CTA pair + trust line. All inside the centered card.

### Routed (after server-side routing completes)

Status trail step 2 marked done; new step 2 label visible (e.g., "রাউটেড / Routed" + time); step 3 marked current. No card reflow.

### In progress

Step 3 marked done; step 4 marked current. No card reflow.

### Resolved

All 4 steps marked done; trail collapses to a "Resolved" badge; CTA pair remains (left: "View report", right: "Back to home"). Body shows a brief celebratory mini-message: "আপনার রিপোর্ট সমাধান হয়েছে! / Your report is resolved!" No confetti animation in v1 — earned emotion, not performative.

### Offline submit

Offline banner visible at top of the status trail inside the card. Rest of card is identical.

### Network failure (during polling)

Status trail freezes at last known state; a small inline notice "আপডেট পেতে সমস্যা হচ্ছে / Updates paused" appears below the trust line inside the card. Polling retries automatically.

## Success

Rahim sees the centered card, the check, the ticket ID, and the status trail. Within minutes (often seconds), step 2 lights up — Routed. He feels **heard**. He taps "View report" to see his full activity, or "Back to home" to keep browsing. The card is identical on his phone and on his laptop at home.

**Emotional outcome:** This is the screen where Rahim's skepticism begins to lift. The status trail is the *visible proof* that CityFix is not a black hole. The next time he has a problem, he'll come back faster.

---

## Open Questions

- **Celebration copy on resolve** — currently a brief mini-message. **Default:** restrained. No confetti animation in v1 — earned emotion, not performative.
- **Status poll interval** — 10–30s. **Default for v1.** Adjust post-launch if it consumes too much battery.
