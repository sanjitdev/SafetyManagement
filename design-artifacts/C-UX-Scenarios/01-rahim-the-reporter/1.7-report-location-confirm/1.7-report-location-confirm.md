# Report Flow — Location Confirm

**Route:** `/report/location`
**Scenario:** Rahim the Reporter — Reports a broken streetlight (screen 7 of 14)
**Purpose:** Capture Rahim's GPS location and let him adjust it on the map before he commits to anything else.

> **Phase B (2026-10-04):** Location Confirm is now a **two-region web layout** at large viewport: map fills the left region (1fr), a side card with location metadata + Confirm CTA fills the right region (`--report-side-panel`, 480px). At medium viewport the card collapses below the map. The Confirm CTA is in-flow inside the side card, not sticky-bottom. The full-bleed mobile map + sticky CTA pattern is replaced. See `_progress/00-design-log.md` for the re-skin.

---

## User Context

Rahim arrives here from the Home floating Report CTA. He is in the moment, on the street, looking at the broken streetlight. He wants to confirm where he is without doing any typing. If the GPS is right, this is one tap.

## Content & Actions

### Page container

- **Page name:** `report-location-page`
- **Language:** Bangla default.
- **Layout (web-first, large viewport ≥ 1025px):** the page is split into a top bar (`--header-height-desktop`, 64px) + a two-region body. Left region (1fr) is the **map** with a draggable pin anchored to the viewport center. Right region (`--report-side-panel`, 480px) is a **side card** carrying the progress strip, location metadata (ward, lat/long), and the Confirm CTA. The map fills the available height; the side card scrolls independently if its content exceeds the viewport.
- **Layout (medium viewport ≤ 1024px):** the same top bar collapses to `--header-height-mobile` (56px). The body reflows to a single column: map on top (60% of remaining height), side card below (40%).
- **At all viewports:** the **Confirm CTA is in-flow inside the side card** (not sticky-bottom). The step progress strip is the first item inside the side card.

### Header (top bar)

- **`report-location-header`** — `--header-height-desktop` (64px) at large viewport, `--header-height-mobile` (56px) at medium; same surface as the rest of the top bars in the app.
- **Left:** close ×. Tap → confirm dialog "রিপোর্ট বাতিল করবেন?" / "Discard report?" with "Discard" and "Keep editing" buttons.
- **Center:** "ধাপ ১ / ৪: লোকেশন / Step 1 of 4: Location".
- **Right:** (empty — no menu on this flow).

### Progress indicator (inside the side card, top of right region)

- **`report-progress-bar`** — full-width strip just below the header inside the side card. 4 segments; first segment filled in primary color; remaining three in muted grey. On phone-width / medium viewports the progress bar is still the first item in the side card, now below the map.

### Map (main view, left region at large / top region at medium)

- **`report-location-map`** — OpenStreetMap tiles (MapLibre recommended per WO-001), centered on Rahim's current GPS location.
- **`report-location-pin`** — large draggable pin in the center of the map, anchored to the detected GPS coordinate by default.
- **Drag the map** to recenter the pin (the pin stays anchored; the map moves beneath it). Standard pattern: pin is fixed at viewport center, dragging the map moves the pin's world coordinate.
- **Map controls (overlay, top-right of the map region):** zoom in / zoom out (36×36 white square buttons, identical to Home).

### Side card (right region at large / bottom region at medium)

- **`report-location-card`** — `--color-surface-card` background, internal padding `--space-5`, vertical stack:
  - **`report-location-ward`** — auto-detected ward name, large body type, e.g., "ওয়ার্ড ১৪, মিরপুর / Ward 14, Mirpur".
  - **`report-location-coords`** — small caption in `--color-ink-tertiary`, e.g., "23.806°N, 90.368°E" (read-only). Updates in real time as the pin moves.
  - **`report-location-helper`** — small helper text "ম্যাপে পিন সরিয়ে সঠিক জায়গায় বসান / Drag the pin to set the right location." (Bangla: "ঠিকানা সেট করতে পিন সরান।")
  - (gap of `--space-5`)
  - **`report-location-button-confirm`** — primary CTA, full-width inside the side card, `--touch-large` (56px) tall, label "এই লোকেশন ব্যবহার করুন / Use this location". Tap → routes to `/report/photo`.

### Primary action (in side card)

- **`report-location-button-confirm`** — primary CTA inside the side card, full-width, `--touch-large` (56px) tall.
  - **Label (BN):** "এই লোকেশন ব্যবহার করুন"
  - **Label (EN):** "Use this location"
  - Tap → routes to `/report/photo`.

## Behavior

### GPS capture

- On screen load, app calls `navigator.geolocation.getCurrentPosition()` with a 10-second timeout.
- **Success:** map centers on the coordinate; pin anchored.
- **Failure (timeout, permission denied, signal):** map centers on Dhaka/Chattogram city center; a small inline message appears below the map: "আপনার লোকেশন পাওয়া যাচ্ছে না — ম্যাপে ম্যানুয়ালি সেট করুন" / "Couldn't find your location — set it manually on the map." User can drag to position the pin manually.

### Permission handling

- If location permission was never asked, prompt is shown here (not on Welcome — see Welcome spec rationale).
- If user denies: same fallback as GPS failure above.

### Pin dragging

- The pin is fixed at viewport center.
- Dragging the map moves the pin's world coordinate.
- On every drag-end, the ward-detection API is called and `report-location-ward` updates.
- The coordinate display `report-location-coords` updates in real time.

### Confirm flow

- Tap CTA → POSTs `{lat, long, ward_id, ward_name}` to local state (no server call yet — the report is not submitted until the final submit at `/report/note`).
- App routes to `/report/photo` with location preserved.

### Back navigation

- × button → confirm dialog. **Discard** clears all local report state and routes back to `/home`. **Keep editing** returns to the map.

## States

### Default (GPS acquired)

Map centered on user's location; pin anchored at viewport center; side card shows ward name + coordinates + helper text; CTA enabled.

### GPS unavailable

Map centered on city center; pin still draggable; helper message shown inside the side card; CTA enabled.

### Loading (waiting for GPS)

Map shows city center with a faint grey pulse indicator on the pin; CTA disabled (greyed out).

### Confirming (mid-tap)

CTA shows spinner briefly as it transitions to the photo step.

## Success

Rahim taps Report on Home, lands on this screen, sees his location is correctly detected (or drags the pin 10 meters to fine-tune), taps "Use this location" within 5 seconds, lands on Photo Capture.

**Emotional outcome:** Rahim feels the system is **using his context automatically** — no address typing, no city/ward selection, no friction. This is the first concrete signal that CityFix is different from government forms.

## Open Questions

- **Manual address entry** — should there be an option to type an address if GPS is wrong? **Default for v1: no.** Map pin adjustment is the manual path. Address-text input is a v2 candidate.
- **Ward detection** — requires a reverse-geocoding API that maps lat/long → ward polygon. **Default:** call `/api/v1/wards/lookup?lat=...&long=...` once on pin drag-end. Implementation detail for Mimir.
