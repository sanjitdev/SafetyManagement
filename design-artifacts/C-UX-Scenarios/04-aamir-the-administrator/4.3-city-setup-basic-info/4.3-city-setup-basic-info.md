# City Setup — Basic Info

**Route:** `/admin/cities/{city_id}/setup` or `/admin/cities/new/setup`
**Scenario:** Aamir the Administrator — Sets up Chattogram (screen 3 of 7)
**Purpose:** Capture the foundational info for a new city: name, code, authority contacts, languages, brand accents.

---

## User Context

Aamir is starting a new city (Chattogram). Before he can configure wards, departments, or categories, he needs to register the city's identity — name, the city corporation it covers, who the chief dispatcher is, and which languages to enable.

---

## Content & Actions

### Page container

- **Page name:** `admin-city-setup-basic-page`
- **Language:** Bangla default (the admin UI is in Bangla even when configuring cities that use English-primary).
- **Layout:** Two-column desktop (left: form, right: live preview). Stacks vertically on tablet.

- **`admin-city-setup-basic-button-save`** — sticky-bottom, full-width within form column.

## Behavior

### Auto-save

- Form auto-saves every 30 seconds if there are unsaved changes.
- A small inline indicator shows "সংরক্ষণ হচ্ছে… / Saving…" during the save.

### Validation

- City code must be unique across all cities.
- At least one language is required.
- Email fields must be valid format.

### Live preview

- The preview column updates on each keystroke (debounced 200ms).

### Unsaved changes guard

- If Aamir tries to navigate away with unsaved changes, a confirmation modal appears.

### Hardware-key requirement

- Save action requires the hardware key (re-prompt modal opens if not authenticated in the last 5 minutes).

---

## States

### Default (empty form)

Empty fields; preview shows placeholder.

### Filling

Live preview updates; save status shows "সংরক্ষণ করতে হবে / Unsaved."

### Saving

Inline "সংরক্ষণ হচ্ছে… / Saving…" indicator; inputs disabled.

### Saved

Status changes to "সংরক্ষিত / Saved"; routes to next step.

### Validation error

Inline errors next to fields; save blocked.

### City code conflict

Inline error: "এই কোড ইতিমধ্যে ব্যবহৃত / This code is already used."

### Network failure

Toast at the bottom; status reverts to "Unsaved."

### Hardware-key required

WebAuthn modal opens; form disabled.

## Success

Aamir fills out Chattogram's basic info, watches the preview reflect his inputs, taps Save. City transitions from "Planned" to "Setup" stage. He is routed to the next step (Departments & Categories).

**Emotional outcome:** Aamir feels the platform **carries the structure** — he provides the city's identity, the platform handles the rest of the rollout.

---

## Open Questions

- **Brand customization** — should each city have its own logo / accent color? **Default for v1: yes**, with one accent color picker. Logo upload is a v1.1 enhancement.
- **Multiple city corporations per city** — some cities have multiple corporations (e.g., Dhaka North + Dhaka South). **Default for v1: one city = one authority in the system.** Multi-authority support is a v1.1 enhancement.
