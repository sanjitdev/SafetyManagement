# User Provisioning

**Route:** `/admin/cities/{city_id}/setup/users`
**Scenario:** Aamir the Administrator — Sets up Chattogram (screen 6 of 7)
**Purpose:** Provision the people who will run CityFix in this city: dispatchers, crew members, and any read-only supervisors.

---

## User Context

Aamir is configuring Chattogram. He needs to add the people who will actually use the platform: 5 dispatchers (one per ward cluster), 12 crew members (organized into 4 crews), and 2 supervisors. Each person gets a role, an identifier, and an initial password.

## Behavior

### CSV import

- File picker accepts .csv files with columns: `name_bn, name_en, identifier, email, role, wards_or_crew, department`.
- On import: rows are validated; errors are shown with row numbers.
- Successful rows are saved; failed rows are shown in a table the user can fix and re-upload.

### Invitation flow

- New users with status = "Invited" receive an SMS or email with a one-time link to set their password.

### Auto-save

- Edits auto-save every 30s.

### Validation

- Identifier must be unique across the city.
- Dispatchers must be assigned to at least 1 ward.
- Crew members must be assigned to 1 crew and 1 department.
- Initial password must meet complexity rules (≥ 8 chars, mixed).

### Hardware-key requirement

- Delete and bulk operations require the hardware key.

## States

### Default (no users)

Empty list with "Add user" CTA.

### User list populated

Cards visible; default tab = All.

### Adding (form open, empty)

Form fields empty.

### Editing (form populated)

Form fields pre-filled; Delete button visible.

### CSV importing

Modal with progress bar.

### CSV import error

Modal with list of failed rows.

### Validation warning

Inline errors next to fields.

### Network failure

Toast; unsaved changes queued.

## Success

Aamir adds 19 users to Chattogram (5 dispatchers, 12 crew members, 2 supervisors) using the CSV import from the city corp's HR roster. He assigns each dispatcher to their wards, each crew member to their crew. He taps Launch. Total time: under 15 minutes.

**Emotional outcome:** Aamir feels the platform **handles the people-side** — naming, roles, assignments. He is not building an org chart from scratch.

## Open Questions

- **Multi-city users** — should Aamir be able to assign one user to multiple cities? **Default for v1: no.** Each user belongs to exactly one city.
- **Role hierarchy** — supervisor → dispatcher → crew. **Default for v1: flat hierarchy** with no reporting lines. Org-chart is a v1.1 enhancement.
