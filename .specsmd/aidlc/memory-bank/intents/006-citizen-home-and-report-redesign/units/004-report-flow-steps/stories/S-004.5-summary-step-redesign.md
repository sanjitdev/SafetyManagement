# Story S-004.5 — Summary step redesign (FR-8)

## As a

Citizen about to submit my report

## I want

A 2-column confirmation surface (mini-map + first photo on the
left, summary card on the right) where I can review everything
and tap "Edit" on any row to fix it

## So that

I never submit a report with the wrong location, category, or
note — and I never have to start over to fix one detail.

## Acceptance Criteria (BDD)

### Given
The current `/report/summary` page shows a flat list of
summary rows.

### When
The construction agent redesigns the page to:
- Left column (1 col on mobile): a mini-map (240×240) with the
  pin, plus a 240×240 thumbnail of the first photo (or a
  placeholder if no photos).
- Right column (stacked on mobile): a summary card listing
  category, ward, note, photo count — each as a row with a
  small "Edit" text button that returns to the matching step
  (e.g. "Edit" next to "Location" routes to `/report/location`).
- Below the card: a "Confirm" checkbox ("আমি নিশ্চিত যে উপরের
  তথ্য সঠিক" / "I confirm the above information is correct")
  and a single "Submit report" primary button (full-width on
  mobile).
- On submit: button shows a loading state (spinner + "জমা
  হচ্ছে…") for the duration of the network request, then
  routes to `/report/[id]/submitted` on success or shows an
  inline error card on failure.

### Then
- "Edit" buttons are keyboard-focusable and announce their
  target step (e.g. "Edit location").
- Submit is gated on the "Confirm" checkbox; without it, the
  button is disabled.
- The mini-map is read-only (no drag, no zoom — just visual
  confirmation).
- The loading state has `aria-busy="true"`.
- The inline error card has a "Try again" button that retries
  the submit.
- axe-core shows zero serious or critical issues.

## Story Notes

- The submit endpoint is the existing `POST /api/v1/tickets`;
  no backend change.
- The "জমা হচ্ছে…" ("Submitting…") copy comes from
  `lib/i18n/keys.ts`.
- The summary card is a `<section>` element; the "Edit" buttons
  are `<a>` elements (Next.js `<Link>`) for navigation, not
  `<button>` (no form submit semantics).
