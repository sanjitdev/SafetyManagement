# Story S-004.3 — Category step redesign (FR-6)

## As a

Citizen picking the category of my report

## I want

A grid of category cards (icon + Bangla name + English name +
chevron) and a search filter at the top, so I can find the
right category in 2 taps

## So that

The category list feels browsable, not overwhelming, even when
the city adds 30+ categories.

## Acceptance Criteria (BDD)

### Given
The current `/report/category` page shows a flat list of
categories fetched from `/api/report/bootstrap`.

### When
The construction agent redesigns the page to:
- A search/filter input at the top of the page.
- A 2-column grid of category cards (1 column on mobile).
- Each card: icon (lucide-react), Bangla name (large),
  English name (small, secondary), chevron (right).
- Selected state: `--color-accent` 2dp border,
  `--color-primary-soft` background, checkmark icon top-right.

### Then
- Tapping a card selects it instantly; "Continue" enables.
- The search filter is debounced 200ms, case-insensitive, and
  matches against the Bangla or English name.
- Long category lists scroll within the card region; the page
  itself does not scroll on desktop.
- Cards are keyboard-navigable (Tab to focus, Enter to select,
  arrow keys to move within the grid), with a 3-4dp focus ring.
- axe-core shows zero serious or critical issues.

## Story Notes

- The category list is fetched from `/api/report/bootstrap`
  (existing endpoint; no change).
- The card grid uses CSS Grid (not flex); `grid-template-columns:
  repeat(auto-fill, minmax(240px, 1fr))` for the desktop layout
  to support future > 2 columns if the city adds more
  categories.
