# Story S-004.2 — Photo step redesign (FR-5)

## As a

Citizen adding photos to my report

## I want

A big primary action area ("Add photo") and a horizontal
thumbnail strip of the photos I've already added, with a clear
counter ("1 of 3 added") and a caption explaining why photos help

## So that

I can add up to 3 photos in 2 taps each and never lose track of
how many I've added.

## Acceptance Criteria (BDD)

### Given
The current `/report/photo` page lets the user add photos via a
file input.

### When
The construction agent redesigns the page to:
- A primary "Add photo" action area (camera icon + label, 96dp
  tall, full-width on mobile).
- A thumbnail strip (horizontal scroll) showing the current
  photos with a small "X" to remove each.
- A caption: "ছবি যোগ করলে দ্রুত সমাধান হয়" (Adding photos
  speeds resolution).
- A counter: "1 of 3 added" (or "1 of 2 added" for narrow
  categories).
- The narrow-category cap (2 for narrow categories) is enforced:
  when the cap is reached, the primary action area is disabled
  with a tooltip "Maximum 2 photos for this category".

### Then
- The photo strip is keyboard-navigable (Tab through thumbnails,
  Enter on the remove "X").
- The "Continue" button is disabled until ≥ 1 photo is added.
- Tapping the primary area on a mobile device with
  `getUserMedia` support opens the camera; otherwise it falls
  back to the file picker.
- The narrow-category cap is reflected in the counter and
  disables the primary area when reached.
- axe-core shows zero serious or critical issues.

## Story Notes

- Per the v1 spec, the cap is 3 photos for most categories and
  2 for narrow categories. The category choice from step 3
  drives the cap; the photo step reads it from form state.
- Per Checkpoint 2 default: the CTA copy is "Add photo" (not
  "Take photo") so it works on desktop too.
