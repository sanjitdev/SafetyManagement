# Story S-002.1 — Side-panel hierarchy + Filter chip group

## As a

Citizen landing on `/home` to find an open report near me

## I want

The right-hand side panel to show a clear hierarchy — sticky
header with the city name + filter affordance, then a scannable
list of report cards (status pill, category + ward, age, truncated
note)

## So that

I can scan the list in 2–3 seconds and tap the report I want
without parsing a busy wall of text.

## Acceptance Criteria (BDD)

### Given
The home page renders the side panel with a list of report cards,
each currently showing category, ward, status, note, and age in a
flat layout.

### When
The construction agent restructures the side panel to:
- A sticky top header with city name (left) and a "Filter" chip
  group (right) using `<FilterChipGroup>` from Unit 003 with
  options `["All", "Open", "Mine"]`.
- Each report card uses `<ReportCard variant="list">` (status pill
  left, category + ward middle, age right, note as one
  ellipsis-truncated secondary line).

### Then
- The sticky header remains visible at all scroll positions within
  the panel.
- Selecting a filter chip updates the list to the matching
  subset; the selection is reflected in the URL as
  `?filter=open|mine|all` (default: all).
- The filter chip group is keyboard-navigable (Tab to focus, Enter
  to select, ← / → arrows to move between chips), with a 3-4px
  visible focus ring (`--color-border-focus` or equivalent token).
- The list is denser (each card is shorter than the v1 baseline)
  but never below 56dp tall (so cards are still 44dp+ tappable).
- axe-core shows zero serious or critical issues on `/home` for
  the side panel.

## Story Notes

- The filter chip group reuses the primitive from Unit 003.
- The "Mine" filter requires the citizen to be logged in; the
  chip is hidden if the user is anonymous (or shown as disabled
  with a tooltip "Sign in to filter by your reports").
- The status pill color is standardized via Unit 003
  (`<StatusPill>`).
