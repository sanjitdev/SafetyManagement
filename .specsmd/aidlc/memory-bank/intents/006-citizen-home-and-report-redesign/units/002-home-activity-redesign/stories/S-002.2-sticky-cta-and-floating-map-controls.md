# Story S-002.2 — Sticky CTA + Floating map controls

## As a

Mobile citizen scrolling the home page

## I want

The "Submit a report" CTA to be sticky at the bottom of the
viewport at all times, and the map controls (zoom, recenter,
locate-me) to live in a floating cluster in the bottom-right of
the map

## So that

I can start a report in 1 tap from any scroll position, and the
map controls don't fight the side panel for screen space.

## Acceptance Criteria (BDD)

### Given
The home page renders a primary "Submit a report" CTA inside the
side panel (desktop) or below the map (mobile), and a set of map
controls (zoom +/-/recenter/locate-me) sitting in a corner of the
map.

### When
The construction agent:
- Pins the "Submit a report" CTA to the bottom of the panel on
  desktop and to the bottom of the viewport on mobile (sticky
  position, full-width, ≥ 56dp tall).
- Moves the map controls to a floating action cluster in the
  bottom-right of the map (`--color-surface-card` background,
  48dp touch targets, 4dp corner radius, subtle shadow).

### Then
- On a 375px viewport, the CTA is reachable in ≤ 1 tap from any
  scroll position (always visible at the bottom of the viewport).
- On a 1024px+ viewport, the CTA is at the bottom of the side
  panel, always visible as the panel scrolls.
- Each map control has a 48×48dp touch target (per FR-2 + WCAG
  2.5.5 AAA).
- The floating control cluster has a 12dp margin from the map
  edges and does not overlap with the pin popups.
- The controls are keyboard-focusable; each has an `aria-label`
  (e.g. "Zoom in", "Zoom out", "Recenter on Dhaka",
  "Locate me").

## Story Notes

- The cluster pattern is a Material/Floating UI pattern; the
  visual treatment uses the existing `--color-surface-card` token
  (now white in the new palette).
- The locate-me button falls back gracefully if
  `navigator.geolocation` is denied.
