# Story S-002.3 — Pin selected/unselected states

## As a

Citizen scanning the home map for an open report

## I want

Each pin to clearly show whether it's the one I'm currently
focusing on, and tapping a pin should select it (URL updates, side
panel scrolls to the matching card)

## So that

I never confuse "the report I clicked" with "another report near
it" — and I can deep-link to a specific report from the URL bar.

## Acceptance Criteria (BDD)

### Given
The home map renders one pin per ticket; the v1 pin is a single
filled circle with a category color.

### When
The construction agent updates the pin component to:
- **Selected**: filled `--color-accent` circle with a 4dp outer
  ring (sky-700 at 100%, 4dp ring in `--color-accent-hover` at
  50% alpha).
- **Unselected**: white circle with `--color-border-strong` border
  and category-color fill at 70% opacity.
- On click: pin becomes selected, URL updates to
  `?ticket=<id>`, side panel scrolls to the matching card (with
  the card highlighted briefly via a `--color-primary-soft`
  flash).

### Then
- The selected pin is visually distinct from unselected pins
  (≥ 3:1 contrast per WCAG 1.4.11).
- Selecting a pin never deselects it on its own; only another
  pin click or a deselect button clears the selection.
- The URL is shareable: reloading the page with `?ticket=<id>`
  in the URL restores the selected state and scrolls to the card.
- Pin density of 200 per viewport maintains ≥ 30 FPS (the
  existing MapLibre cluster pattern is preserved; no change to
  data flow).

## Story Notes

- The pin click is a `<button>` (not a `<div>`) for keyboard
  accessibility; Enter / Space activate it.
- Aria-label on each pin is `<ticket id> — <category> — <ward>`.
- The "highlight flash" is a 1.2s `--color-primary-soft` background
  pulse; collapses to instant under `prefers-reduced-motion`.
