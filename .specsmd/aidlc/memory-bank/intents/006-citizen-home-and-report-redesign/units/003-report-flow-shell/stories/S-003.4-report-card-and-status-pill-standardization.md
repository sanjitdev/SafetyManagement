# Story S-003.4 — ReportCard + StatusPill standardization

## As a

Library author building the home side panel and any future
ticket list surface (admin, dispatcher, crew)

## I want

A reusable `<ReportCard variant="list" | "map">` and a
`<StatusPill status="submitted | routed | in-progress | resolved | closed">`
that share a consistent visual + ARIA contract

## So that

Every ticket-list surface renders the same row rhythm and the
same status semantics.

## Acceptance Criteria (BDD)

### Given
A ticket has `id`, `category`, `ward`, `status`, `note`, `age`,
and (for the map variant) `lat`/`lng`.

### When
The construction agent renders
`<ReportCard ticket={ticket} variant="list" />` or
`<ReportCard ticket={ticket} variant="map" />`.

### Then
- The **list variant** shows: status pill (left), category +
  ward (middle), age (right), with the note as a one-line
  ellipsis-truncated secondary line below. Card height ≥ 56dp
  (tappable), `<button>` element (keyboard accessible).
- The **map variant** shows: status pill (top-left), category
  (bottom-left), age (top-right) — designed to overlay on a map
  popup. Not tappable (the map pin is the tappable element).
- The `<StatusPill>` is a small pill with:
  - `submitted` — neutral gray (`--color-ink-tertiary` background
    or `--color-surface-raised` background + `--color-ink`
    text).
  - `routed` — info blue (`--color-accent` background, white text).
  - `in-progress` — amber (custom token, e.g.
    `--color-warning-soft` background, `--color-warning` text).
  - `resolved` — green (custom token, e.g.
    `--color-success-soft` background, `--color-success` text).
  - `closed` — neutral gray.
  Each pill is a `<span>` with `aria-label="Status: <status>"`.
- Vitest unit tests cover: (a) list variant default, (b) map
  variant default, (c) each status pill variant, (d) ellipsis
  truncation on long notes, (e) ARIA labels.

## Story Notes

- The warning + success color tokens may be added in Unit 001's
  `tokens.css` edit if they don't already exist. No new token
  names beyond what's already in the spec; if `warning` /
  `success` aren't in the file, the construction agent proposes
  the additions in the PR.
- The map variant is used by the existing map popup component
  (the design lives in the home unit, not here — this story only
  ships the primitive).
