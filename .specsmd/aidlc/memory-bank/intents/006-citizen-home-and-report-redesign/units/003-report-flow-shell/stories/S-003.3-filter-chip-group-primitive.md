# Story S-003.3 — FilterChipGroup primitive (keyboard + ARIA)

## As a

Library author building any filterable list (home side panel,
category search, future admin filters)

## I want

A reusable `<FilterChipGroup>` component that renders a
keyboard-navigable, ARIA-correct radio-group of chip-style options

## So that

Filter UIs across the app share one accessible, consistent
implementation.

## Acceptance Criteria (BDD)

### Given
A page needs a filter (e.g. the home side panel: "All / Open /
Mine"; or a future category filter: "Infrastructure / Sanitation /
Safety").

### When
The construction agent renders
`<FilterChipGroup options={...} value={...} onChange={...} />`.

### Then
- Each chip is a `<button>` with `role="radio"` and
  `aria-checked={value === option.value}`.
- The chip group has `role="radiogroup"` with an `aria-label`
  (e.g. "Filter reports").
- Keyboard: Tab focuses the group; ← / → arrows move between
  chips; Enter / Space select the focused chip; Home / End jump
  to first / last.
- The selected chip has `--color-accent` background and white
  text; unselected chips have `--color-surface-card` background
  and `--color-ink` text with `--color-border` border.
- Each chip has a 3-4dp visible focus ring on `:focus-visible`.
- Touch target ≥ 44×44dp.
- A Vitest unit test covers: (a) default render, (b) selection
  change fires `onChange`, (c) keyboard navigation, (d) ARIA
  attributes are present.

## Story Notes

- The component is purely presentational; it does not own the
  filtered list state.
- The "Mine" filter (home side panel only) is hidden when the
  citizen is anonymous — that's a caller-side decision, not the
  component's.
